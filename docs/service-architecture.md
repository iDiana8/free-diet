# Архитектура сервиса Free Diet

## Назначение

Free Diet - это сервис для личного ведения питания за день. У каждого пользователя есть свой аккаунт, и все записи дневника, заметки и аналитика привязаны именно к нему.

## Слои приложения

### Frontend

`frontend/` отвечает за:

- регистрацию и вход пользователя;
- хранение токена сессии в браузере;
- отображение планшета;
- работу с блоками питания;
- локальный пересчёт калорий и БЖУ до сохранения;
- отправку данных в backend.

### Backend

`backend/` отвечает за:

- регистрацию пользователя;
- вход пользователя;
- проверку токена авторизации;
- валидацию входных данных;
- чтение справочника продуктов;
- сохранение личного дневника питания и заметок;
- расчёт сводной аналитики по выбранной дате.

### Database

PostgreSQL хранит:

- пользователей;
- личные цели по питанию;
- каталог продуктов;
- дневные записи;
- список продуктов, воды и напитков по выбранной дате.

## Поток данных

1. Пользователь регистрируется или входит.
2. Backend возвращает токен и данные пользователя.
3. Frontend хранит токен в `localStorage`.
4. При загрузке дневника frontend отправляет авторизованный запрос `GET /api/daily/:date`.
5. Backend по токену определяет пользователя и загружает только его записи.
6. При сохранении frontend вызывает `PUT /api/daily/:date`.
7. Backend обновляет дневник именно этого пользователя.
