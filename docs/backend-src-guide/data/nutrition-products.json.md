# `src/data/nutrition-products.json`

## Что это
Большой JSON-файл со справочником продуктов питания/напитков и их пищевой ценностью.

## Что там написано
Каждая запись обычно содержит:
- `name` — имя продукта.
- `name_normalized` — нормализованное имя для поиска и дедупликации.
- `product_kind` — тип (`food`, `drink`, `water`).
- `unit_label` — единица (`г` или `мл`).
- `base_amount` — базовое количество (обычно 100).
- `calories`, `protein`, `fat`, `carbs` — нутриенты на `base_amount`.
- `allowed_sections` — допустимые секции дневника.
- `source_label` — источник данных.

## Почему так пишут
- База на 100 г/мл делает масштабирование порции простым (`amount / base_amount`).
- `allowed_sections` фиксирует доменные ограничения (например, напитки в `drinks`).
- Нормализованное имя помогает искать и блокировать дубли.

## С чем связано
- Загружается в `services/catalog.service.js`.
- Участвует в заполнении таблицы `nutrition_products`.
- Используется косвенно в `daily.service.js` через получение каталога.

## На что влияет
- На полноту каталога.
- На точность расчетов dashboard.
- На UX выбора продуктов.

## Что будет, если этого файла не будет
- `syncNutritionCatalog` потеряет основной источник seed-данных.
- Каталог станет неполным (останутся только вручную добавленные записи, если они есть).

## Тезисно
- Это "доменные данные", а не бизнес-алгоритм.
- Формат файла напрямую определяет корректность расчетов и фильтров.
