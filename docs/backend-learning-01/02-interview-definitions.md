# Определения для собеседований (JS + Backend)

## База
- Функция (function) — блок кода, который можно вызвать, передав аргументы, и получить результат.
- Метод (method) — функция, которая хранится как свойство объекта и вызывается через этот объект.
- Аргумент (argument) — конкретное значение, переданное в функцию при вызове.
- Параметр (parameter) — переменная в объявлении функции, которая принимает аргумент.
- Модуль (module) — отдельный файл/единица кода с экспортом и импортом.
- Зависимость (dependency) — внешняя библиотека, которую проект подключает через пакетный менеджер.

## Backend
- Backend — серверная часть приложения: бизнес-логика, БД, API, авторизация.
- Endpoint — конкретный HTTP-адрес + метод (например `PUT /api/daily/:date`).
- Route (маршрут) — правило, по которому сервер направляет запрос в обработчик.
- Middleware — промежуточная функция в HTTP-цепочке (например проверка токена).
- Service layer — слой бизнес-логики между роутами и БД.
- DTO / Payload — объект данных запроса/ответа.
- Validation — проверка входных данных по правилам до бизнес-логики.
- Health-check — endpoint, который показывает, что сервис работает.

## База данных
- Pool (пул подключений) — набор переиспользуемых соединений с БД.
- Транзакция (transaction) — группа операций, которые фиксируются вместе (`COMMIT`) или откатываются (`ROLLBACK`).
- Constraint — ограничение БД (например `UNIQUE`, `NOT NULL`).
- Индекс (index) — структура для ускорения поиска.
- Seed data — стартовые данные для первичного наполнения БД.
- Upsert — вставка или обновление записи при конфликте.

## Безопасность
- Salt — случайная добавка к паролю перед хешированием.
- Hash — необратимое представление данных фиксированной длины.
- Token — строка, подтверждающая авторизацию пользователя.
- Bearer token — токен в заголовке `Authorization: Bearer <token>`.
- Signature (подпись) — криптографическая проверка, что токен не подменен.

## Качество кода
- Unit test — тест отдельной функции/модуля в изоляции.
- Regression — поломка ранее работавшего поведения.
- Refactoring — изменение внутренней структуры без изменения внешнего поведения.
- Coupling (связность модулей) — степень зависимости модулей друг от друга.
- Cohesion (цельность модуля) — насколько задачи модуля логически связаны.
